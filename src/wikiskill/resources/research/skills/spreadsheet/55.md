# SpreadsheetBench Concrete-Value Workbook Editing

## Objective

Edit the supplied workbook with bash or Python and save the completed file as `output.xlsx`. Write concrete values, never formulas, into the exact answer region while preserving unrelated workbook content, structure, and formatting.

## Non-Negotiable Rules

- Copy the source workbook before editing it. Never overwrite the source.
- Save exactly one completed workbook at the requested `output.xlsx` path.
- Do not insert, delete, sort, or rebuild rows, columns, tables, or sheets unless the task explicitly requires that structural operation.
- Do not add explanations, helper tables, headers, labels, or annotations outside the established answer region.
- Write no formulas into the answer region, including formulas that are expected to calculate to constants.
- Preserve formulas, values, styles, merged cells, hidden state, validations, objects, and sheet order outside the authorized edit.

## 1. Inspect Before Editing

Load the workbook without discarding formulas and inspect:

- sheet names and used ranges;
- non-empty values and formulas near likely target cells;
- headers, merged cells, tables, named ranges, hidden rows or columns, and repeated blocks;
- styles and number formats that distinguish input, example, answer, and explanation cells;
- task wording, existing formulas, and example results that reveal the intended operation.

When formulas exist, inspect the formula text with `data_only=False`; optionally inspect cached results with `data_only=True` as a separate clue. A cached value can be stale and must not replace analysis of the formula's references, operators, and branches.

Derive and record internally the exact target sheet and rectangle before writing. Separate header cells, data cells, example cells, and neighboring explanation areas. A blank area alone is not proof that every blank cell belongs to the answer.

Prefer an in-place value replacement. If the request names a column or row informally, use workbook structure to determine its first and last answer cells. Do not extend the rectangle merely to make the output look complete.

## 2. Build the Calculation Contract

Before computing, write an internal contract that can predict each answer cell. Record:

- the output unit and source rows or cells;
- grouping, lookup, and ordering keys;
- exact predicates and comparison operators;
- time grain, window anchors, reset points, and evaluation date;
- numerator and denominator populations for every count, rate, or matrix;
- duplicate, tie, unmatched, blank, zero, error, and sentinel behavior;
- output type, precision, and any special-case branches.

Do not leave a contract field implicit because the resulting values look plausible. Infer it from exact task language, original formula references, labels, and multiple consistent examples. If clues conflict, identify the conflicting branch and choose the rule that explains the strongest evidence across ordinary and boundary cases; do not cherry-pick one displayed value or invent a convenient business rule.

Translate any relevant formula into ordinary language operator by operator. Preserve inclusive versus exclusive comparisons, start-of-period versus end-of-period evaluation, rolling-window endpoints, payment or maturity timing, boolean coercion, error handling, and diagonal or other special cases. Rules such as “positive means sold,” “open at any time during the month,” or “fewer than N rows means unavailable” are valid only when workbook evidence establishes them.

Create a state map for every encountered category, including:

- true blank input;
- numeric zero;
- empty text;
- unmatched lookup key;
- missing or unavailable value;
- text markers such as `-`, `N/A`, or `ERROR`;
- non-event or non-payment periods;
- blank lower or upper boundaries;
- other workbook-specific sentinels.

Do not collapse these categories into one default. In particular, never assume that a blank range boundary invalidates a row: workbook formulas or examples may use a blank start or end as an open-ended interval. Determine whether boundaries are inclusive, exclusive, missing, or unbounded from the strongest workbook evidence.

Preserve value types. Write numbers as numbers, dates as dates, booleans as booleans, text markers as text, and true blanks as empty cells. Do not replace an unmatched result with zero, a dash, or an empty string unless the workbook contract supports that exact mapping.

## 3. Compute Concrete Values

Compute results outside the workbook or in memory, then write only final constants into the target rectangle.

- Use source values at their stored precision.
- Do not round intermediate calculations.
- Store the full numeric result unless the task explicitly requires a rounded constant.
- Use the existing number format to control displayed decimals, percentages, currencies, dates, or labels.
- For lookups, define normalization deliberately and detect duplicate keys rather than silently taking an arbitrary match.
- For date, range, and running-total tasks, test the first row, last row, boundary rows, and reset points explicitly.

For every aggregate, explicitly name the counted unit, grouping keys, time grain, numerator predicate, denominator population, and missing-period policy. Distinguish all rows from eligible rows, records from distinct entities, fixed populations from populated periods, and point-in-time status from overlap during a period. Do not infer a denominator from the table size or percentage format.

For sorting, filtering, insertion, or deduplication, represent each source row as an atomic record such as `(sheet, original_row, key, payload)`. Build the expected output sequence from those record identities before writing. Preserve duplicates and stable source order by default; deduplicate only when the instruction or repeated workbook evidence defines both the duplicate key and the survivor rule. A duplicate key is not automatically a duplicate record, and a pre-sized answer block is not proof that records should be dropped.

If the workbook contains an example-result block, use it to infer and test the contract. Copy it only when the task clearly establishes a direct cell-for-cell or key-for-key correspondence.

## 4. Verify Independently

Mechanical validation is necessary but does not prove that the values are correct. Perform both mechanical and semantic verification after saving.

### Mechanical checks

Reopen `output.xlsx` and confirm:

- the expected sheets still exist in the same order;
- the target rectangle contains concrete values and no formulas;
- values have the intended spreadsheet types;
- number formats and relevant styles are preserved;
- no unexpected rows, columns, sheets, merges, or tables were added or shifted;
- changes outside the authorized region are absent, except for explicitly requested structural edits.

Do not erase or rewrite unrelated pre-existing formulas merely to make a workbook-wide formula count reach zero.

### Semantic checks

Verify results through a path independent from the production calculation:

- manually enumerate source rows for at least two representative answer cells;
- include boundary cases and at least one example from every encountered blank, zero, unmatched, sentinel, open-ended, or special-branch category;
- for aggregates, show the contributing records and recompute both numerator and denominator, then check one edge case where membership changes;
- for lookups, display the matched source key and source row and test a boundary or unmatched key;
- for ordered results, compare the complete output sequence of source record identities, including duplicates and ties;
- for running calculations, independently reconstruct the sequence around reset and boundary rows;
- compare raw stored numbers, not only rendered text, using exact comparison for identifiers, counts, categories, and booleans and a justified tolerance for calculated decimals.

The independent check must not call the same helper or reuse the same derived result that produced the workbook values. Reloading successfully, finding no formulas, or reproducing the same values with the same assumptions is not semantic verification.

If an independent check disagrees, stop and resolve the contract before finalizing. Reinspect workbook formulas, examples, labels, boundaries, populations, record membership, and sentinel behavior; do not patch only the disagreeing cell.

## 5. Finish

Confirm that `output.xlsx` exists at the exact requested location and opens successfully. Report completion concisely, naming the edited sheet and range and stating that concrete values were written. Do not claim correctness based only on file integrity or absence of formulas.
