# Read Treasury Bulletin Tables Before Calculating

Use the local `.txt` corpus as the evidence source. Treat retrieval as unresolved until you can bind every input to the requested object, period, row, column, sign, unit, and semantic operation.

## 1. Parse the request

Before searching, write an internal extraction specification:

- Identify the requested evidence object: named table, chart, listing, section, or publication.
- Identify the exact measure, including qualifiers such as gross, net, total, component, receipts, outlays, rate, balance, or spread.
- Classify each requested quantity as a direct level, period flow, change in a cumulative series, gross or net amount, named component, transaction subset, total, ratio numerator, or ratio denominator.
- Expand the requested interval into ordered period keys.
- Mark calendar versus fiscal time, monthly versus annual frequency, inclusive endpoints, and expected observation count.
- Record the requested statistic, transformation, output unit, precision, and output order.

Do not silently replace the requested object with related prose, another table, or an external publication. Use related material only to locate or cross-check the requested object.

Do not begin arithmetic until the requested wording maps to an exact source label and semantic operation. If the source supplies only a related total, component, collection concept, or transaction class, keep the requested quantity unresolved rather than treating the substitute as equivalent.

## 2. Locate the table, then inspect its structure

Search distinctive table titles, section labels, row labels, and column labels before searching isolated numbers.

Read enough surrounding text to capture:

- bulletin issue and table identifier;
- full multi-line headers;
- printed unit;
- footnotes and sign conventions;
- whether periods are calendar, fiscal, year-to-date, annual-rate, or rolling;
- whether values are actual, estimated, preliminary, or revised.

For OCR-flattened or interleaved tables, reconstruct the header-to-column mapping from printed labels, partial-year columns, neighboring rows, and totals. Never infer a year or series solely from visual position.

## 3. Build a checked extraction ledger

For every value, retain this internal tuple:

`issue | table | row | column | period | printed value | unit | sign convention | semantic operation`

Attach exactly one value to every requested period key. Stop and re-read the table if the ledger contains a gap, duplicate, unexpected observation count, mismatched row, or unresolved column mapping.

For multi-part questions, map each requested quantity to its source tuple, semantic operation, formula, and output position before calculating. For every ratio, bind numerator and denominator independently to their exact labels, populations, periods, and transaction basis.

Preserve table hierarchy and transaction vocabulary. Do not substitute a parent total for a named component or interchange amounts tendered, accepted, exchanged, allotted, refunded, or held by different participant classes merely because they describe the same security or period.

## 4. Keep one coherent vintage

Prefer one bulletin edition containing the complete requested window. If repeated editions contain the same table, compare overlapping cells for revisions.

Do not silently splice observations from different editions. If one edition cannot cover the window, choose and state internally a consistent vintage rule, then verify each splice through overlapping periods. Resolve conflicting OCR cells with row structure, labels, repeated editions, and printed totals; arithmetic plausibility alone is not evidence.

For transaction questions, keep the operands within the same identified offering or reporting record unless the question explicitly requires a comparison across records. Do not combine a preliminary narrative amount, a later revised table total, and a participant subset without reconciling what each figure includes.

## 5. Resolve units and semantics before arithmetic

Keep extracted values in their printed units. Determine currency quotation direction, percentage basis, sign meaning, and scale from headers or footnotes. Apply conversions in a separate explicit step and convert to the requested output unit only once.

For cumulative tables, decide explicitly whether the requested result is the printed cumulative level or the difference between consecutive levels. Before differencing, verify that adjacent observations share the same definition and that no reset or revision invalidates the subtraction.

Before computing a statistic:

- enumerate the selected observations;
- assert the expected count;
- define the requested estimator or transformation;
- distinguish population from sample statistics when relevant;
- distinguish ordinary changes from annualized, geometric, logarithmic, or compound changes;
- round only the final requested quantities.

If plausible alternatives such as fiscal versus calendar periods, revised versus original values, nearby rows, competing transaction classes, or competing unit conventions materially change the result, return to the source labels and question wording. Do not choose the most plausible-looking result.

## 6. Perform a final provenance check

Before answering, verify that every output quantity can be traced through:

`requested object -> exact table cell(s) -> semantic operation -> explicit transformation -> requested unit and precision`

Reject any quantity whose chain depends on an unstated substitution, guessed header, mixed vintage, missing period, nearby series, mismatched transaction basis, or unsupported external fact.
